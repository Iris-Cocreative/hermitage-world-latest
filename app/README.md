# Hermitage World: the app

The app side of hermitageworld.org: accounts, the shop, free posts, and the team's admin. Next.js 16 on Vercel, Supabase (auth, Postgres, storage), Stripe Checkout. The static site at the repository root is served by the same deployment, so the site and the app share one domain, one stylesheet and one header.

Status and decisions live in `../HERMITAGE-WORLD-BUILD.md` (section "The app").

## How it fits together

```
hermitage-world/            the static site (GitHub Pages serves this today)
  assets/css/app.css        the app's own styles, part of the design system
  app/                      this folder: the Next.js project (Vercel root directory)
    app/(site)/             routes on the site's main.css: shop, posts, account, sign-in
    app/(trellis)/          routes on Trellis: library, all of admin (a root layout of its own)
    app/api, app/auth       route handlers
    components/             app nav, page hero, product files, uploader
    lib/                    Supabase clients, auth, Stripe, markdown, formatting
    supabase/               config, migrations, generated seed
    scripts/                sync-site, seed-catalog, make-staff
    static/                 app-owned public files (robots.txt)
    vendor/                 PINNED copies of Trellis and Collab Library (npm run vendor): never edit
    styles/                 the Trellis pages' own chrome (site-trellis.css)
    public/                 GENERATED by sync-site: never edit, gitignored
```

`npm run dev` and `npm run build` first copy the static site into `public/`, so `/about/`, `/gatherings/` and every other page are served next to the app's routes. App pages link the site's `main.css` and load `site.js`, so `<hw-header>` and `<hw-footer>` are the site's own.

## Run it locally

Node 24 lives in `..\..\.tools\node` on this machine (no system Node). Docker Desktop must be running for the local database.

```bash
export PATH="/c/Users/james/Desktop/Claude Code/.tools/node:$PATH"
cd app
npm install
npm run db:start          # local Supabase on ports 544xx; applies migrations and the seed
npm run db:status         # prints the local URL and keys
```

Create `.env.local` from `.env.example`. For local work:

- `NEXT_PUBLIC_SUPABASE_URL` = `http://127.0.0.1:54421`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` = the publishable (or anon) key from `db:status`
- `SUPABASE_SECRET_KEY` = the secret (or service_role) key from `db:status`

Then:

```bash
node scripts/make-staff.mjs you@example.com a-password   # an admin who can sign in with a password
npm run dev                                              # http://127.0.0.1:4100
```

Emails sent by the local stack (sign-in links) are caught at http://127.0.0.1:54424.

Known quirk (2026-11-07, Next 16.2.10 with Turbopack on Windows): twice the dev server stopped answering every request after a file was edited while a page was open. If `npm run dev` goes quiet, stop it (Ctrl+C, or kill the process on port 4100) and start it again; nothing is lost.

Useful:

| Command | What |
|---|---|
| `npm run db:reset` | Rebuild the local database from `supabase/migrations/` and `supabase/seed.sql` |
| `npm run db:types` | Regenerate `lib/supabase/database.types.ts` after a schema change |
| `npm run seed:catalog` | Regenerate `supabase/seed.sql` from `../assets/data/catalog.js` (68 draft products) |
| `npm run seed:library` | Regenerate `supabase/seed-library.sql`: the catalog as Collab Library resources, linked to those products |
| `npm run vendor` | Pin Trellis and Collab Library from the sibling folders into `vendor/` (and the library's schema into `supabase/migrations/0002_collab_library.sql`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run sync` | Copy the static site into `public/` without starting the server |
| `node scripts/test-webhook.mjs` | With the dev server running: posts a signed fake `checkout.session.completed` to the webhook and prints the paid order, the buyer's profile and the entitlement. Needs `STRIPE_WEBHOOK_SECRET` in `.env.local` (any string locally) |

## Stripe, locally

Install the CLI once (`npm i -g @stripe/cli`), then either sign in to the Hermitage's Stripe account (`stripe login`) or make a throwaway sandbox (`stripe sandbox create`). Put a **restricted key** (`rk_test_…`, with Checkout Sessions write) in `.env.local` as `STRIPE_SECRET_KEY`, and run:

```bash
stripe listen --forward-to http://127.0.0.1:4100/api/stripe/webhook
```

It prints a signing secret (`whsec_…`): that is `STRIPE_WEBHOOK_SECRET`. Test cards: `4242 4242 4242 4242`, any future date, any CVC.

The webhook is where a purchase becomes real (order marked paid, entitlement granted). The thank-you page only reports. Never skip the webhook in production.

## Deploy

1. **Supabase**: create a project (Iris Cocreative org), then from `app/`: `supabase link --project-ref <ref>` and `npm run db:push`. Run the seed by pasting `supabase/seed.sql` into the SQL editor if the catalog is wanted. In Authentication → URL configuration set the site URL and add `https://<domain>/auth/confirm/**` to the redirect list. Make the first admin with `node scripts/make-staff.mjs` pointed at the project (env vars from the project's API settings).
2. **Stripe**: a live restricted key; a webhook endpoint at `https://<domain>/api/stripe/webhook` subscribed to `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`.
3. **Vercel**: import the repo, set **Root Directory** to `app`, keep "Include source files outside of the Root Directory" on (the build copies `../assets` and the site pages). Environment variables as in `.env.example`; mark the secret ones sensitive.

## What exists (2026-11-07)

- Sign in by email link or password (`/sign-in/`), sign out, session refresh in `proxy.ts`.
- Shop (`/shop/`, `/shop/<slug>/`): active products grouped by kind; buy through Stripe Checkout; free items go straight into the library; an album lists its tracks.
- Library (`/account/`): what a person owns, with streaming and download through `/api/media/<id>/` (signed URLs, one hour), and their orders.
- Posts (`/posts/`): published posts, letters, news and teachings, in Markdown.
- Admin (`/admin/`, staff and admin roles): products with cover and file uploads straight to storage, posts, orders, counts.
- Database: `supabase/migrations/0001_init.sql`: profiles (role), products, product_files, orders, order_items, entitlements, stripe_events, posts, two storage buckets, row-level security throughout.

## The library (2026-11-19)

`/library/` and `/library/<slug>/` are Collab Library (`../../collab-library`, vendored), on Trellis. Its editor is `/admin/library/` (resources), `/admin/library/paths/` and `/admin/library/kinds/`. A resource that is sold links to its product; the shop decides the price and whether it is on sale. Details: `../HERMITAGE-WORLD-BUILD.md`, section "Collab Library, and the app on Trellis".

Not yet: memberships and the LMS (entitlements are built to take a `membership` source), donations, a real newsletter, emails after purchase, Stripe Tax, a content-security policy, tests.
